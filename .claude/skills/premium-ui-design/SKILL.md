# premium-ui-design

تصميم واجهات احترافية فاخرة لمثقال ضمن الهوية المعتمدة (كحلي وذهبي، IBM Plex Sans Arabic وManrope): التسلسل البصري، الكثافة، الحالات، والتفاصيل الدقيقة. استخدمها عند تصميم شاشة جديدة أو تحسين شاشة قائمة.

## متى تُفعَّل المهارة
- تصميم أو تحسين شاشة أو نافذة أو نموذج.
- مراجعة «الشاشة تبدو غير احترافية».

## متطلبات التنفيذ
- `brand/mithqal-brand-tokens.css`، `styles.js`، `docs/UI_UX_DESIGN_STANDARDS.md`.
- **لا هوية بديلة** ولا ألوان خارج الرموز.

## خطوات العمل
1. عنصر رئيسي واحد لكل شاشة (الرقم أو الإجراء الأهم) بأعلى تباين.
2. الذهبي للتمييز فقط (الإجراء الأساسي، المؤشر النشط)، لا للمساحات الكبيرة.
3. المسافات من السلم 4/8/12/16/24/32 فقط؛ المحاذاة لشبكة.
4. الأرقام بخط MizanNum، محاذاة نهاية الخلية، السالب بين قوسين وبالأحمر.
5. كل شاشة لها حالات: فارغة بإرشاد، تحميل، خطأ بحل، نجاح، لا صلاحية.
6. حركة خفيفة فقط (`--t-fast`/`--t`)، ومع `prefers-reduced-motion` تُلغى.

## المعايير المحاسبية أو الهندسية ذات الصلة
WCAG 2.2 AA (تباين 4.5:1 للنص، 3:1 للعناصر)، أهداف لمس ≥ 44px.

## أمثلة عملية
بطاقة KPI: العنوان 12px رمادي، الرقم 24px كحلي MizanNum، المقارنة شارة صغيرة خضراء/وردية، بلا ظلال ثقيلة.

> كل الأرقام في الأمثلة وهمية. المستودع عام: لا تكتب بيانات المنشأة الحقيقية.

## حالات الخطأ
- لون مكتوب يدويًا (#hex) خارج الرموز ← يرفضه `design-lint`.
- نص أبيض على ذهبي ← تباين ضعيف؛ استخدم الكحلي على الذهبي.

## اختبارات التحقق
- `node tests/ai-team/design-lint.mjs`.
- لقطات حقيقية بالعربية والإنجليزية، جوال وحاسوب.

## المخرجات المطلوبة
- مواصفة الشاشة + لقطات قبل/بعد.

## قواعد عامة
- لا افتراض لقاعدة عمل غير موثقة؛ ارفعها للمالك.
- لا يعتمد المنفذ عمله بنفسه: المخرج يمر على المدقق المستقل المناسب (`accounting-validation-agent` أو `design-quality-auditor` أو `security-auditor`).
- نجاح البناء أو التوازن وحده ليس دليل صحة.
