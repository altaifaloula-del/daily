# general-ledger

الأستاذ العام والقيود اليومية وميزان المراجعة في مثقال: دليل الحسابات، القيد المزدوج، الترحيل، العكس، الأرصدة، الإقفال. استخدمها عند مراجعة أو اختبار أو بناء أي شيء يمس القيود أو الأرصدة.

## متى تُفعَّل المهارة
- مراجعة دليل الحسابات أو قيد أو رصيد أو ميزان مراجعة.
- بناء أو تعديل دالة تولّد قيودًا.
- تحقيق في فرق بين تقريرين.

## متطلبات التنفيذ
- `buildAccounting(org, ops)`، `glLedger(A, code, opts)`، `acctActivity(A, opts)`، `jeLive`، `periodLocked`، `fpLockedTo` في `App.jsx`.
- بيانات اختبار وهمية فقط.

## خطوات العمل
1. ارسم دليل الحسابات: الرمز، الاسم، النوع (asset/liability/equity/revenue/expense)، الطبيعة (مدين/دائن).
2. لكل قيد تحقق: Σمدين = Σدائن، تاريخ داخل فترة مفتوحة، حسابات موجودة ونهائية (لا ترحيل على حساب رئيسي)، مصدر مرجعي (رقم مستند).
3. الرصيد الختامي = الافتتاحي + Σمدين − Σدائن (للحسابات مدينة الطبيعة)، والعكس للدائنة.
4. ميزان المراجعة: Σالأرصدة المدينة = Σالأرصدة الدائنة، ويساوي مجموع الأستاذ لكل حساب.
5. العكس: قيد عكسي بنفس المبالغ بتبديل الجانبين ومرجع للقيد الأصلي؛ لا حذف.
6. تحقق أن القيد الملغى/المسودة (`status != posted`) لا يدخل الأرصدة (`jeLive`).

## المعايير المحاسبية أو الهندسية ذات الصلة
- القيد المزدوج: كل حدث يؤثر على حسابين على الأقل بمجموعين متساويين.
- عدم القابلية للتعديل بعد الترحيل: التصحيح بقيد عكسي/تسوية مع أثر في `audit_log`.
- الترقيم المتسلسل للقيود اليدوية (`pjNumber`) بلا فجوات غير مفسّرة.
- فصل المهام: منشئ القيد لا يعتمده (`canApproveJe`).
- الفترة المقفلة لا تقبل قيودًا (`periodLocked`).

## أمثلة عملية
**قيد إغلاق يومي (وهمي)، الضريبة مفعّلة 15%، مبيعات شاملة 1,150:**
| الحساب | مدين | دائن |
|---|---|---|
| 1111 صندوق الفرع (نقدي) | 690 | |
| 1201 البنك — الشبكة | 460 | |
| إيراد المبيعات | | 1,000 |
| ضريبة المخرجات | | 150 |
المجموع 1,150 = 1,150. التوازن وحده لا يكفي: يجب أن يكون الإيراد صافيًا والضريبة منفصلة.

> كل الأرقام في الأمثلة وهمية. المستودع عام: لا تكتب بيانات المنشأة الحقيقية.

## حالات الخطأ
- قيد غير متوازن ← يُرفض ولا يُرحّل.
- ترحيل مكرر لنفس المستند ← يُكشف بمفتاح المصدر.
- قيد في فترة مقفلة ← يُرفض.
- فرق تقريب بالهللات ← يُعالج بقاعدة تقريب موثقة لا بإخفائه.

## اختبارات التحقق
- `node --test tests/validation/*.test.mjs` (المحرك المستقل).
- `npm run test:acct` (اختبارات المحرك القائمة).
- حالة: Σالميزان مدين = دائن بعد كل سيناريو.

## المخرجات المطلوبة
- تقرير أرصدة: الحساب، افتتاحي، مدين، دائن، ختامي، متوقع، فرق.

## قواعد عامة
- لا افتراض لقاعدة عمل غير موثقة؛ ارفعها للمالك.
- لا يعتمد المنفذ عمله بنفسه: المخرج يمر على المدقق المستقل المناسب (`accounting-validation-agent` أو `design-quality-auditor` أو `security-auditor`).
- نجاح البناء أو التوازن وحده ليس دليل صحة.
