# منصة سحابية متكاملة لإدارة وإغلاق فروع المطاعم
Cloud Restaurant Closing & Management Platform — نسخة تشغيلية جاهزة للبناء والنشر.

## التشغيل السريع

```bash
npm install
cp .env.example .env      # اختياري: لتفعيل المدير المالي الذكي
npm run dev               # الخادم + واجهة التطوير معاً → http://localhost:3000
```

## البناء والإنتاج

```bash
npm run build             # يبني الواجهة في dist/
npm start                 # يشغّل الخادم ويخدم dist → http://localhost:8787
```

## الوحدات

- **لوحة المؤشرات** — إيراد ومصروف وصافي وهامش، فروقات الصندوق، أداء الفروع، قنوات التحصيل، والنشاط اللحظي.
- **الإغلاق اليومي** — أربع خطوات: المبيعات، المصروفات، جرد الفئات النقدية، الترحيل — مع التوقيع الرقمي وطباعة إيصال 80 مم.
- **التدقيق والاعتماد** — مرحلتان: تدقيق مالي ثم اعتماد نهائي، مع الإرجاع المبرَّر للفرع.
- **الخزينة الرئيسية** — سندات التوريد، أوامر الصرف بحدود الرصيد، وكشف حركة برصيد تراكمي.
- **الرواتب والسلف** — كشف شهري بصافي المستحق، وتسجيل السلف والخصومات والجزاءات.
- **الموردون والالتزامات** — فواتير آجلة بسداد جزئي، وإيجارات وفواتير الفروع الشهرية.
- **الورديات والتذكيرات** — عدّاد حي لموعد الإغلاق لكل فرع وإعدادات التنبيه.
- **أرشيف المستندات** — التقاط الإيصالات بالكاميرا أو رفعها مع ضغط تلقائي.
- **التقارير** — أداء الفروع + قائمة الدخل الشهرية وضريبة القيمة المضافة، مع تصدير CSV.
- **المركز المالي الذكي** — تحليل CFO عبر وسيط الخادم الآمن.
- **الإدارة** — الفروع، المستخدمون والصلاحيات، بنود المصروف وميزانياتها، بيانات المنشأة، النسخ الاحتياطي، والصيانة.
- **سجل التدقيق** — قيد لكل إجراء بالمستخدم والدور والوقت.

## المزامنة متعددة المستخدمين

كل الحسابات تعمل على قاعدة بيانات واحدة على الخادم. الواجهة تزامن كل 8 ثوانٍ (وتتوقف عند إخفاء التبويب)، وكل كتابة تمر بمراجعة إصدار: تقرأ الأحدث، ترفع الرقم، وتتحقق أن كتابتها ثبتت، وتعيد المحاولة عند التعارض. عند انقطاع الخادم يتحول التخزين تلقائياً إلى نسخة المتصفح المحلية مع بانر تنبيه.

## تفعيل Firestore (الوضع الموصى به للإنتاج)

المنصة تعمل على Firestore تلقائياً بمجرد ضبط المتغيرات في `.env`:

1. أنشئ مشروعاً في Firebase وفعّل **Firestore Database** و**Anonymous Authentication**.
2. انسخ إعدادات تطبيق الويب إلى `.env` (المتغيرات التي تبدأ بـ `VITE_FIREBASE_`).
3. ارفع قواعد الأمان: `firebase deploy --only firestore:rules` (الملف `firestore.rules` مرفق).
4. أعد البناء: `npm run build`.

عندها تتحول المزامنة إلى **لحظية** عبر `onSnapshot` بدل الاستطلاع الدوري، وتظهر كلمة «لحظي» بجانب عدّاد المتصلين. القيم الكبيرة تُقسَّم تلقائياً على مستندات فرعية تفادياً لحد الميغابايت لكل مستند، ويعمل تخزين Firestore دون إنترنت تلقائياً.

إذا تُركت متغيرات Firebase فارغة، تعمل المنصة على خادم المشروع (`data/store.json`) — مناسب للتجربة والشبكة المحلية.

**ترتيب الطبقات:** Firestore ← خادم المشروع ← تخزين المتصفح المحلي عند انقطاع الشبكة.

## النشر على الإنترنت

المنصة تُنشر كخدمة Node واحدة: الخادم يخدم الواجهة المبنية ويؤمّن وسيط الذكاء المالي في آنٍ معاً.

### الطريقة الموصى بها — Render أو Railway

1. ارفع المشروع على GitHub.
2. أنشئ خدمة Web جديدة واربطها بالمستودع (ملف `render.yaml` مرفق ويضبط كل شيء تلقائياً).
3. أضف متغيرات البيئة في لوحة الخدمة:
   - `ANTHROPIC_API_KEY` — للمركز المالي الذكي.
   - متغيرات `VITE_FIREBASE_*` — **مطلوبة وقت البناء** لأن Vite يدمجها في حزمة الواجهة.
4. أوامر الخدمة:
   - البناء: `npm install && npm run build`
   - التشغيل: `node server.js`
   - فحص الصحة: `/api/health`

بعد أول نشر ناجح ستحصل على رابط مثل `https://your-app.onrender.com` تفتحه الفروع من أي مدينة.

### النشر بحاوية Docker

```bash
docker build -t rms-platform \
  --build-arg VITE_FIREBASE_API_KEY=... \
  --build-arg VITE_FIREBASE_PROJECT_ID=... \
  --build-arg VITE_FIREBASE_AUTH_DOMAIN=... \
  --build-arg VITE_FIREBASE_STORAGE_BUCKET=... \
  --build-arg VITE_FIREBASE_SENDER_ID=... \
  --build-arg VITE_FIREBASE_APP_ID=... .

docker run -p 8787:8787 -e ANTHROPIC_API_KEY=... rms-platform
```

تعمل الصورة كما هي على Google Cloud Run و Fly.io و أي VPS.

### تنبيه مهم قبل النشر

استضافات السحابة تمسح نظام الملفات عند كل إعادة نشر، أي أن `data/store.json` **يُفقد**. لذلك عند النشر على الإنترنت اضبط متغيرات Firestore حتماً — عندها تُحفظ كل البيانات في Firestore ولا يُستخدم ملف الخادم أصلاً.

### بعد النشر مباشرة

1. سجّل الدخول بحساب الإدارة العليا.
2. غيّر رموز الدخول لكل المستخدمين من: الفروع والمستخدمون ← تعديل ← رمز الدخول السريع.
3. حدّث بيانات المنشأة والرقم الضريبي.
4. اضغط «إعادة ضبط بيانات العرض» لمسح البيانات التجريبية قبل بدء التشغيل الفعلي.
