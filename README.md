# مثقال (Mithqal) — منصة إدارة المطاعم متعددة الفروع

> الإصدار: **v46.9** — فرع التطوير: `mithqal-erp-2` — الشعار: «منصة واحدة، لكل الأعمال ومن أي مكان» — One platform for every business, from anywhere.
> سابقًا: «ميزان» و«منصة الإغلاق اليومي».

منصة سحابية عربية (RTL) مع دعم الإنجليزية: الإغلاق اليومي، المحاسبة بالقيد المزدوج، المخزون والمشتريات،
نقاط البيع، الموارد البشرية والرواتب، الفوترة الإلكترونية (ZATCA)، والتقارير التنفيذية.

---

## المتطلبات

| الأداة | الإصدار |
|---|---|
| Node.js | 22 LTS أو أحدث (Node 20 انتهى دعمه) |
| npm | 10+ |
| Java 21 | فقط لتشغيل اختبارات قواعد Firestore على المحاكي |

## التشغيل المحلي (تطوير)

```bash
npm ci                    # تثبيت مطابق لملف القفل
cp .env.example .env      # ثم املأ القيم التي تحتاجها
npm run dev               # الخادم (8787) + واجهة التطوير → http://localhost:3000
```

إذا تُركت متغيرات `VITE_FIREBASE_*` فارغة تعمل المنصة على تخزين الخادم المحلي (`data/store.json`) — للتجربة فقط.

## الدخول

لا توجد حسابات أو رموز دخول افتراضية. الدخول ببريد وكلمة سر عبر **Firebase Authentication**:
المالك ينشئ حسابه من شاشة الدخول بزر «الإعداد الأول بعد الترقية (للمالك)»، ثم يضيف بقية المستخدمين وأدوارهم وفروعهم من الإدارة.
يمكن فرض التحقق الثنائي (MFA) من الإدارة وسير العمل `enable-mfa.yml`.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run build` | بناء الواجهة في `dist/` |
| `npm start` | تشغيل الخادم في وضع الإنتاج ويخدم `dist/` |
| `npm test` | اختبارات المحرك المحاسبي + ZATCA + النسخ الاحتياطي + الإشعارات (بلا محاكي أو متصفح) |
| `npm run test:rules` | اختبارات قواعد Firestore على المحاكي (تحتاج Java) |
| `npm run test:ui` | اختبارات الواجهة بـ Playwright/Chromium (جوال وحاسوب) |
| `npm run test:all` | كل ما سبق |
| `npm run check` | بناء + `npm test` قبل أي رفع |

```

```

## النشر

الدليل الكامل: **`PROJECT_AUDIT/DEPLOYMENT_GUIDE.md`**. باختصار:

1. **الواجهة** → GitHub Pages عبر `.github/workflows/deploy.yml` (عند الرفع على `main` فقط، وبعد نجاح الاختبارات).
2. **قواعد Firestore والفهارس** → سير عمل منفصل `firestore-rules.yml` (أو `firebase deploy --only firestore:rules,firestore:indexes`).
3. **الخادم** (الذكاء الاصطناعي + الفوترة) → Render عبر `render.yaml`، أو Docker.

### الأسرار

| المكان | الاسم | ملاحظة |
|---|---|---|
| GitHub Secrets | `VITE_FIREBASE_*` (ستة) | إعدادات تطبيق الويب — عامة بطبيعتها لكنها تُدار كأسرار |
| GitHub Secrets | `FIREBASE_SERVICE_ACCOUNT` | حساب الخدمة (نسخ احتياطي، إشعارات، نشر القواعد، MFA) |
| GitHub Secrets | `BACKUP_KEY` | تشفير النسخ الاحتياطية — احفظ نسخة منه خارج GitHub |
| GitHub Secrets/Vars | `VITE_AI_ENDPOINT`، `VITE_AI_FEEDBACK_ENDPOINT`، `VITE_FCM_VAPID_KEY` | اختيارية |
| الخادم فقط | `ANTHROPIC_API_KEY`، `FIREBASE_API_KEY`، `ZATCA_ENC_KEY`، `ALLOWED_ORIGINS` | **لا تضع أي سرّ خادم في متغير يبدأ بـ `VITE_`** |

### قاعدة ذهبية

لا تعدّل `firestore.rules` وترفعها دون تشغيل `npm run test:rules`. أي تساهل في القواعد يكشف البيانات المالية.

## ملاحظات

- الضريبة 15% (تُحسب ضمنًا 15/115 حيث ينطبق). القوائم المالية لأغراض الإدارة ولا تحل محل القوائم المعتمدة من المحاسب القانوني.
- الفوترة الإلكترونية: بيئتا المطورين والمحاكاة فقط. بيئة الإنتاج لدى «فاتورة» غير مفعّلة، ولا يُعد النظام متوافقًا إنتاجيًا قبل اجتياز متطلبات الربط الرسمية.
