## 2) أين تُفرض الصلاحية فعليًا

| الطبقة | ماذا تفرض | الحالة | الدليل |
|---|---|---|---|
| الواجهة (`ROLES.tabs`، `safeTab`) | إظهار التطبيقات حسب الدور، ونطاق الفرع `scope: own` | PASS | اختبارات الواجهة 18، 29، 30، 55 (فريق الفرع لا يرى الربحية ولا طلبات غيره، مراقب التكاليف بلا إضافة) |
| قواعد Firestore — عضوية وعزل الفروع | زائر/حساب بلا عضوية لا يقرأ؛ كل عضو لمستند فرعه | **BLOCKED** | 69 اختبار قواعد موجود؛ لم يُشغَّل (المحاكي يحتاج firebase-tools وتنزيل ملف المحاكي — الشبكة مقفلة في هذه الجلسة). Java متوفر |
| قواعد Firestore — سجلات الإغلاق المستقلة | انتقالات الحالة الموقّعة (مسودة ← مرسل ← معتمد ← اعتماد المدير) | PASS في الكود / BLOCKED تشغيلًا | `firestore.rules` 305–360. **لكنها مطفأة افتراضيًا** (اختبار UI 35) |
| **إقفال الفترة** | منع تغيير قيود شهر مقفل | **PARTIAL — الواجهة فقط** | الحارس `lockedLedgerChanged` يعمل عند الحفظ من المنصة (اختبار الدورات 7)، لكن لا قاعدة خادم تمنعه — عضو بصلاحية كتابة على مستند فرعه يستطيع تجاوزه عبر API |
| **الإغلاق المعتمد** | منع تعديله دون إجراء معتمد | **PARTIAL** | محمي بالخادم فقط عند تفعيل «سجلات الإغلاق المستقلة»؛ في الوضع الافتراضي الحماية في الواجهة |
| القيد اليدوي | التوازن + منع الشهر المقفل | PARTIAL — الواجهة | المحرك **يكشف** القيد غير المتوازن إن وصل مباشرة (اختبار الدورات 6) ويظهر في «صيانة النظام»، لكنه لا يُمنع عند الكتابة |
| الخادم `server.js` | العضوية النشطة لنقاط الذكاء والفوترة؛ أدوار الفوترة | PASS بالمراجعة | لم يُختبر حيًّا (المرحلة 2) |

## 3) الحكم
- **صلاحيات العرض:** مطبقة ومختبرة.
- **الحماية من الخادم:** لا يمكن الحكم عليها قبل تشغيل اختبارات القواعد. أهم فجوة مؤكدة من قراءة القواعد: إقفال الفترات وثبات المعتمَد يعتمدان على الواجهة في الوضع الافتراضي (GAP-003، GAP-004).
