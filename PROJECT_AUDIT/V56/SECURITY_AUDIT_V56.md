## 2. حدود ما تفرضه القواعد (صريح)
- البيانات التشغيلية الأساسية ما زالت **نصًا مضغوطًا** في `platform/rms8_*`. القواعد تفرض **من** يكتب كل مستند (المنشأة للمدير، المركزي للمركز، الفرع لفرعه، العرض فقط لا يكتب) لكنها **لا تستطيع فحص محتواه**. لذلك عضو مركزي يملك الكتابة على `rms8_core` يستطيع تقنيًا عبر API كتابة محتوى يتجاوز حراس التطبيق (الإقفال، التكرار، الرصيد السالب).
- الحماية الكاملة على مستوى المحتوى قائمة الآن للسجلات المستقلة (`closings`، `fin_journal`، `fin_docs`، `fin_periods`، `signoffs`، `audit_log`) وتصبح المصدر بعد خطوات GAP-004 التشغيلية. سجل التدقيق المحصّن (`audit_log`، لا يُعدَّل ولا يُحذف) وفحوص السلامة تكشف ما يُكتب خارج المسار.

## 3. المصادقة والجلسات
- الخادم يتحقق من الرمز عبر `accounts:lookup` بمفتاح المنشأة نفسها، ويرفض اختلاف المشروع، ويقرأ العضوية برمز المستخدم نفسه (القواعد تطبَّق)، ويفرض الخطوتين بسياسة القواعد ذاتها.
- جلسة واحدة لكل مستخدم: دخول جديد يُخرج الجلسة الأقدم (`kickOut`).
- **مفتوح V56-019 (P1):** القواعد لا تشترط `email_verified` والتسجيل الذاتي مفعّل ⇒ خطر انتحال بريد موظف أُضيفت عضويته قبل إنشاء حسابه. يحتاج قرار المالك.
- **V56-022 (P3):** التخزين المؤقت لنتيجة التحقق دقيقتان على الخادم.

## 4. الأسرار
- مسح كل commits هذا المستودع وملفات المصدر: لا مفاتيح (أنماط Google `AIza`، Anthropic `sk-ant-`، GitHub، AWS، Stripe live/test، PEM، `private_key`). `.env.example` قيم وهمية فقط. لا ملف `.env` ولا حساب خدمة.
- **سجل git الأصلي للمشروع (commits مثل `77cbe84`) غير مُرفق في الحزمة فلم يُفحص هنا** — يغطيه `security-scan.yml` (gitleaks على كامل السجل) في المستودع الأصلي.
- مفاتيح الواجهة (`VITE_*`) عامة بطبيعتها؛ مفتاح Anthropic ومفتاح ZATCA على الخادم فقط.
- BUG-012 أُصلح (V56-007): مفتاح ZATCA لا يُولَّد تلقائيًا، وبصمته تكشف أي تغيّر.
