# SECURITY AUDIT

## ما فُحص في الدفعة 1
- **تسريب الأسرار:** مسح المستودع (دون node_modules و.git) عن مفاتيح Google API ومفاتيح Anthropic ومفاتيح خاصة PEM ← لا شيء. لا ملف `.env` مرفوع.
- **ملاحظة:** النسخة المسحوبة سطحية (آخر commit فقط) — **سجل git القديم لم يُفحص**. يُنصح بفحصه بـ gitleaks في CI.
- **حماية الرفع العرضي:** أُضيفت أنماط `.env.*` وحسابات الخدمة (BUG-005).
- **أسرار الخادم:** `.env.example` يحذّر من وضع أي سرّ في `VITE_*`. `server.js` لا يفعّل `/api/store` غير المصادق في الإنتاج أو مع Firebase — وأصبح Procfile يضبط الإنتاج صراحة.
- **الحاوية:** تعمل بمستخدم `node` غير جذري؛ HEALTHCHECK مضاف.

## معلّق للمراحل اللاحقة
- `server.js` (المرحلة 2): المصادقة، CORS، حد المعدل، حجم الطلبات، عزل المنشآت.
- `firestore.rules` (المرحلة 11): عزل الفروع، حماية الرواتب والحسابات البنكية، المستندات المقسمة. **69 اختبار قواعد موجود لم يُشغَّل في هذه البيئة.**
- نقطة يجب فحصها: زر «الإعداد الأول للمالك» ينشئ حساب Firebase Auth لأي بريد — يجب التأكد في القواعد أن الحساب بلا عضوية نشطة لا يقرأ شيئًا، وأن تأسيس أول مالك لا يمكن تكراره على منشأة قائمة.
- `npm audit` وفحص الاعتماديات آليًا في CI.
