# SMART POS GROWTH — المرحلة B: بنية التكامل وخطة البيانات

## الوحدة
مركز جديد «التسويق والنمو الذكي» (`HUBS.growthmkt`) بتبويب صلاحية `mkt` يُضاف إلى أدوار الإدارة؛ الشاشات في `mods/mkt/`.
الحسابات النقية في `App.jsx` (قابلة للاختبار عبر `tests/build-engine.mjs`).

## المجموعات الجديدة (إضافية فقط — لا حذف ولا إعادة تسمية)
| المجموعة | المكان | الغرض |
|---|---|---|
| `org.mkt` | مستند org | الإعدادات: قواعد الشرائح، حدود الخصم والاعتماد، القنوات، الاحتفاظ |
| `mktConsents` | CORE | سجل موافقات/إلغاء اشتراك غير قابل للتعديل (إلحاق فقط) |
| `mktMerges` | CORE | دمج عملاء معتمد (من ← إلى، المعتمِد، السبب) |
| `mktCampaigns` | CORE | الحملات وحالاتها ومسار الاعتماد (المرحلة F) |
| `mktCouponUse` | مستند مشترك بكتابة مشروطة | استخدامات الكوبونات (المرحلة E) |
| `mktRecEvents` | BR | أحداث التوصيات: عرض/قبول/رفض (المرحلة G) — **نُفّذت داخل الطلب** (`recShown`/`recDismissed`/`line.rec`) بدل مجموعة مستقلة، انظر G_REPORT |
| `mktComms` | CORE | سجل الرسائل وحالتها (المرحلة I) |
| `mktExpenses` | CORE | مصروفات التسويق (تُرحَّل محاسبيًا عبر السندات القائمة) |
| `loy.tx` (قائم) | مستند الولاء | حركات جديدة: tier/adj/expire/merge — إلحاق فقط |

لا فهارس SQL (Firestore مستندي)؛ كل تغيير مخطط = حقل/مجموعة جديدة بقيم افتراضية فارغة، فلا ترحيل مدمّر.

## الصلاحيات
- `mkt` في `tabs` لعرض الوحدة؛ `mktApprove` (المالك/الإدارة) لاعتماد الحملات والخصومات فوق الحد ودمج العملاء.
- النطاق: بيانات العميل تُقصر على طلبات فروع `myBranches` للمستخدم.

## المراحل
C أساس + صلاحيات · D CRM وشرائح · E ولاء وكوبونات · F حملات · G توصيات عند الدفع · H تقارير الفروع · I التواصل · J المساعد الذكي.
كل مرحلة: اختبارات محرك + واجهة + الانحدار الكامل قبل الدمج.
