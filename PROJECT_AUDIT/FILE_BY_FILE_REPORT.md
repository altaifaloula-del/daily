# FILE BY FILE REPORT

> «مكتمل» = فُحص كاملًا، وأُصلح ما ثبت، ونُفّذ اختبار فعلي. «يحتاج مراجعة» = لم يمكن اختبار جانب منه في هذه البيئة.

## المرحلة الأولى

### 1. package.json — مكتمل
- **الوظيفة:** تعريف الحزمة والاعتماديات والأوامر.
- **الأخطاء:** BUG-003 (google-auth-library غير معلنة)، BUG-004 (لا يوجد `npm test` موحد)، الاسم/الإصدار `restaurant-cloud-closing-platform@1.0.0` لا يعكسان v46.7، لا يوجد `engines`.
- **الإصلاح:** الاسم `mithqal@46.7.0`، `engines.node >=22`، `google-auth-library ^9.15.1` (نفس النسخة المثبتة عابرًا 9.15.1 — لا تغيير فعلي في الحزم)، أوامر `test` و`test:all` و`check`.
- **الاختبار:** فحص آلي لتطابق كل اعتمادية مع ملف القفل (semver) ← 0 تعارض. `npm test` ← 108/108.
- **المتبقي:** `npm audit` لم يُشغَّل (لا شبكة) — مضاف لـ CI في المرحلة 13.

### 2. package-lock.json — مكتمل
- **الإصلاح:** مزامنة الجذر (الاسم، الإصدار، devDependencies، engines) مع package.json فقط. لم يُحدَّث أي إصدار حزمة.
- **أبرز الإصدارات المقفلة:** react 18.3.1، vite 6.4.5، firebase 12.19.0، express 4.22.2، @anthropic-ai/sdk 1.6.0، firebase-tools 15.35.0، qs 6.17.1 (override).
- **الاختبار:** تطابق semver (أعلاه). `npm ci` الفعلي معلّق على CI.

### 3. .gitignore — مكتمل
- **الأخطاء:** BUG-005 — يتجاهل `.env` فقط؛ `.env.local` و`.env.production` (يقرؤها Vite) وملفات `*-firebase-adminsdk-*.json` قابلة للرفع بالخطأ.
- **الإصلاح:** `.env.*` مع استثناء `.env.example`، `*.pem`، `*.key`، حسابات الخدمة، `backups/`.
- **الاختبار:** `git ls-files` لا يحتوي أي ملف سري؛ مسح نصي للمستودع عن مفاتيح Google/Anthropic/مفاتيح خاصة ← لا شيء.

### 4. .dockerignore — مكتمل
- **الإصلاح:** نفس أنماط الأسرار + استبعاد `PROJECT_AUDIT`.

### 5. .env.example — مكتمل
- **الأخطاء:** BUG-006 — متغيرات يقرؤها الكود غير موثقة: `ZATCA_ENC_KEY` (بدونه تسجيل أجهزة الفوترة يرجع 503)، `FIREBASE_REFERER`، `VITE_FCM_VAPID_KEY` (الإشعارات)، `VITE_AI_FEEDBACK_ENDPOINT`، وأسرار Actions (`FIREBASE_SERVICE_ACCOUNT`، `BACKUP_KEY`).
- **الإصلاح:** توثيقها مع طريقة التوليد والتحذير من تغيير `ZATCA_ENC_KEY` بعد أول تسجيل.
- **الاختبار:** مقارنة آلية بين كل `process.env.*`/`import.meta.env.*` في الكود والملف.

### 6. README.md — مكتمل
- **الأخطاء:** BUG-007 — رمز دخول `1234` وحسابات تجريبية، «إعادة ضبط بيانات العرض»، «رمز الدخول السريع» (كلها غير موجودة في الكود)؛ تعليمات Firebase Hosting تتعارض مع النشر الفعلي على GitHub Pages؛ عدد اختبارات القواعد «56» والفعلي 69.
- **الإصلاح:** إعادة كتابة مختصرة دقيقة، وإحالة الدليل الكامل إلى `DEPLOYMENT_GUIDE.md`.

### 7. vite.config.js — مكتمل (بلا تعديل)
- **الفحص:** تقسيم الحزم (core، mod-*، vendor-*) سليم؛ وسيط `/api` للتطوير سليم.
- **ملاحظة:** `chunkSizeWarningLimit: 2200` يُخفي تحذير حجم النواة (App.jsx ~1MB) — يُعالج بتقسيم App.jsx في المرحلة 2، لا برفع الحد.
- **الاختبار:** تحزيم كامل بـ esbuild بنفس منطق التحميل عند الطلب ← 109 حزمة.

### 8. index.html — مكتمل (بلا تعديل)
- **الفحص:** RTL، manifest، سكربت إزالة عامل الخدمة القديم يستثني `push-sw.js` بشكل صحيح.
- **ملاحظات للقرار:** العنوان «RESTAURANT PRO» بينما المنتج «مثقال» (قرار هوية — لم يُغيَّر وفق القاعدة 6)؛ `maximum-scale=1` يمنع التكبير باللمس (إمكانية وصول) — يُترك حتى يتأكد أنه غير مقصود لشاشات الكاشير.

### 9. main.jsx — مكتمل (بلا تعديل)

### 10. render.yaml — مكتمل

- **تحذير موثق:** `ZATCA_ENC_KEY: generateValue` — إعادة إنشاء الخدمة تولّد مفتاحًا جديدًا فتتعذر قراءة أسرار الأجهزة المسجلة سابقًا. يجب نسخ المفتاح وحفظه.

### 11. Dockerfile — مكتمل (البناء الفعلي معلّق)

- **الإصلاح:** `COPY zatca ./zatca`، `node:22-alpine`، ARGs الناقصة، HEALTHCHECK على `/api/health`.
- **الاختبار:** محاكاة بنية مرحلة التشغيل: قبل ← `ERR_MODULE_NOT_FOUND .../zatca/onboard.js`؛ بعد ← تُحَل كل الاستيرادات. `docker build` لم يُشغَّل (يحتاج npm).
