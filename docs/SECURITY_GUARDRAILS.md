# حدود الأمان والحماية لفريق الذكاء الاصطناعي — MITHQAL ERP

## 1. القواعد غير القابلة للتجاوز
1. لا حذف لبيانات العملاء.
2. لا تغيير مباشر لمخططات أو بيانات الإنتاج.
3. لا تشغيل لعمليات ترحيل مدمرة.
4. لا تغيير للقيود المالية أو الأرصدة دون موافقة.
5. العمل على بيئة اختبار وفرع تطوير، مع نسخ احتياطية قبل أي تغيير بيانات.
6. لا كشف لكلمات مرور أو مفاتيح أو رموز — ولا ذكر قيمتها حتى في التقارير.
7. احترام صلاحيات كل وكيل (`docs/AI_TEAM_ARCHITECTURE.md` §3).
8. تسجيل التعديلات المهمة (ملاحظات الإصدار، سجل قرارات، `DATABASE_CHANGELOG.md`).
9. مراجعة كل تغيير في قاعدة البيانات أو القواعد قبل تطبيقه (`database-architect` + `security-auditor` + موافقة المالك).
10. لا يعتمد وكيل عمله بنفسه، ولا تُخفى نتيجة فاشلة.

## 2. التنفيذ الفني للحدود
| الحد | آلية الفرض | أين |
|---|---|---|
| منع قراءة الأسرار | `deny`: `.env*`، `*.pem`، `*.key`، حسابات الخدمة، `data/`، `backups/` | `.claude/settings.json` |
| منع النشر | `deny`: `firebase deploy`، `firebase-tools`، `gh workflow run`، الدفع القسري، الدفع إلى `main` | `.claude/settings.json` |
| منع سكربتات الإنتاج | `deny`: النسخ الاحتياطي، الإشعارات، تفعيل MFA، تهيئة المستأجرين، الفوترة | `.claude/settings.json` |
| موافقة قبل التغيير الحساس | `ask`: الدفع، الدمج، طلب الدمج، تثبيت الحزم، قواعد Firestore، الفهارس، سير العمل، `package.json`، البوابة ومحرك التحقق | `.claude/settings.json` |
| حماية الهوية | `deny` تعديل `brand/` و`public/brand/` + بصمة SHA-256 | `.claude/settings.json` + `design-lint` |
| الموافقات الفعلية | `deny` الكتابة في `docs/approvals/granted/` | `.claude/settings.json` |
| أدوات الوكلاء المراجعين | `disallowedTools: Write, Edit, NotebookEdit` | `.claude/agents/*.md` |
| فحص الأسرار | فحص كل الملفات المتتبعة | `scripts/quality-gate.mjs` (`secrets`) |
| فحص القواعد والعزل | محاكي Firestore | `npm run test:rules` |
| فحص الاعتماديات والسجل | npm audit + gitleaks | `.github/workflows/security-scan.yml` (قائم) |

## 3. حدود هذه الآلية (معلنة لا تُخفى)
- قواعد `settings.json` تحكم Claude Code فقط. الحماية النهائية للبيانات هي قواعد Firestore والخادم وصلاحيات Firebase.
- أمر Bash قد يصيغ عملية ممنوعة بطريقة غير مطابقة لنمط المنع؛ لذلك المنع **طبقة إضافية** لا بديل عن عدم إعطاء الجلسة بيانات اعتماد الإنتاج أصلًا.
- **التوصية:** لا تضع `FIREBASE_SERVICE_ACCOUNT` أو مفاتيح الإنتاج في بيئة تعمل فيها جلسات Claude Code.

## 5. الامتثال
- نظام حماية البيانات الشخصية السعودي (PDPL): بيانات العملاء الجدد في `me-central2` (قرار المالك)، الحد الأدنى من البيانات الشخصية في السجلات.
- **لا يُعلن الامتثال الرسمي** (ZATCA، PDPL، أي معيار) دون أدلة ومراجعة المتطلبات والجهات المختصة.

## 6. الاستجابة لحادث
1. أوقف العمل وأبلغ المالك فورًا.
2. لا تحاول «إصلاحًا سريعًا» على الإنتاج.
3. سرّ مكشوف ⇒ إلغاؤه وتدويره من المالك، ثم تنظيف السجل بخطة معتمدة.
4. توثيق الحادث في `PROJECT_AUDIT/ERP_V48/BUGS_AND_ISSUES.md`.
