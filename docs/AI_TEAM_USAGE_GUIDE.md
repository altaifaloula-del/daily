# دليل استخدام فريق الذكاء الاصطناعي — MITHQAL ERP

دليل مبسّط للمالك. لا يحتاج معرفة برمجية.

## 1. التشغيل لأول مرة
1. افتح المشروع في Claude Code (على جهازك أو Cowork) على فرع تطوير، لا على `main`.
2. اكتب `/agents` لترى الوكلاء العشرين، وتأكد أن المهارات ظهرت في قائمة المهارات.
3. شغّل اختبار الإطار: `node --test tests/ai-team/*.test.mjs tests/validation/*.test.mjs`.

## 2. الطريقة الموصى بها: ابدأ بالمنسق
```
claude --agent mithqal-orchestrator
```
ثم اكتب طلبك بالعربية كما تكتبه لمدير مشروع. المنسق سيقسمه ويوزعه ويعود إليك بالخطة والقرارات المطلوبة.

## 3. طلب وكيل بعينه
اكتب في المحادثة: «استخدم الوكيل `accounting-chief` لمراجعة …».

| أريد أن… | اطلب |
|---|---|
| أتأكد أن قيد الإغلاق صحيح | `accounting-chief` ثم `accounting-validation-agent` |
| أراجع ميزان المراجعة أو كشف مورد | `financial-accountant` |
| أفهم تكلفة طبق أو سبب ارتفاع الهدر | `cost-accountant` |
| أتأكد من الفاتورة الإلكترونية أو الإقرار | `zatca-specialist` |
| أراجع الاعتمادات والإقفال الشهري | `financial-controller` |
| أصمم وحدة جديدة | `erp-architect` |
| أضيف مجموعة بيانات أو أرحّل بيانات | `database-architect` (تصميم فقط ثم موافقتك) |
| أحسّن شاشة | `uiux-director` ثم `frontend-engineer` ثم `design-quality-auditor` |
| أصمم تقريرًا للطباعة وExcel | `reports-designer` |
| أيقونة لوحدة جديدة | `icon-designer` |
| أتأكد أن التغيير لم يكسر شيئًا | `qa-engineer` |
| أراجع الأمان والصلاحيات | `security-auditor` |
| أعرف هل الإصدار جاهز | `release-approval-agent` |

## 4. أمثلة جاهزة
- «راجع معالجة عمولات تطبيقات التوصيل في قيد الإغلاق، ولا تعدّل شيئًا.»
- «صمم تقرير كشف حساب لأي حساب في الدليل بالقالب الموحد، وأعطني PDF وExcel تجريبيين.»
- «شغّل بوابة الجودة وأعطني الحكم بلغة بسيطة.»

## 5. الموافقات
عندما يحتاج عمل موافقتك يُنشئ الفريق ملف طلب في `docs/approvals/requests/` فيه: الوصف، السبب، الملفات، المخاطر، نتائج الاختبارات، خطة التراجع.
- للموافقة: انسخ الملف إلى `docs/approvals/granted/` وأضف `status: APPROVED` واسمك والتاريخ (التفاصيل في `docs/approvals/granted/README.md`).
- الوكلاء ممنوعون من الكتابة في مجلد الموافقات الممنوحة.
- **لا تعني الخطة أو الطلب أن الموافقة تمت.**

## 6. قراءة نتيجة البوابة
| الحالة | المعنى | ماذا تفعل |
|---|---|---|
| PASS | كل الشروط تحققت | يمكنك الموافقة على الدمج/النشر |
| CONDITIONAL PASS | ملاحظات غير حرجة موثقة | اقرأ الملاحظات ثم قرر |
| FAIL | فشل شرط إلزامي | لا دمج ولا نشر؛ الفريق يصلح |
| BLOCKED | ينتظر موافقتك أو بيئة ناقصة | وفّر المطلوب المذكور في الأسباب |

اللوحة: `docs/QUALITY_DASHBOARD.md` (تُحدَّث بـ `node scripts/quality-gate.mjs --dashboard`).

## 7. ما لن يفعله الفريق أبدًا دون موافقتك
الدمج في `main`، النشر، تعديل قواعد Firestore، ترحيل أو حذف بيانات، تعديل قيود أو أرصدة، فتح فترة مقفلة، تعديل الهوية.

## 8. استكشاف الأخطاء
| المشكلة | الحل |
|---|---|
| الوكلاء لا يظهرون | تأكد أنك داخل مجلد المشروع، ثم أعد تشغيل Claude Code |
| البوابة BLOCKED بسبب «الاعتماديات غير مثبتة» | شغّل `npm ci` (سيطلب Claude موافقتك) |
| BLOCKED بسبب Java | ثبّت Java 21 لاختبارات القواعد، أو اعتمد على CI |
