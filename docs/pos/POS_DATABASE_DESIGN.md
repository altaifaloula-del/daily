# MUKTASAB POS — تصميم السجلات المستقلة للفواتير (الدفعة 2)

**قرار المالك 2026-11-26:** نقل فواتير نقطة البيع إلى سجلات مستقلة (فاتورة = سجل محمي) **بنسخ موازٍ ثم تحويل**، دون حذف القديم، وبتراجع فوري بمفتاح.
**يحل:** العيب B10 في `POS_AUDIT_REPORT.md` — القواعد اليوم لا ترى فاتورة بعينها لأن الفواتير مصفوفة JSON داخل مستند الفرع/الشهر، فأي عضو في الفرع يستطيع تقنيًا تعديلها أو حذفها.
**النمط:** نفسه المجرَّب منذ v41.9 للإغلاقات (`closings/{id}` + `clrMirror` + `clrCompare` + `clrSeed`).

## 1. المراحل

| الخطوة | ما يحدث | المصدر للقراءة | مفتاح | التراجع |
|---|---|---|---|---|
| **2a — نسخ موازٍ** (هذه الدفعة) | كل فاتورة/مرتجع/إلغاء يُحفظ كما هو في المستند **ثم** يُنسخ بالخلفية إلى `pos_orders/{id}`؛ زر لنسخ التاريخ القديم، وزر مطابقة | المستند (كما اليوم) | `org.posRecords.on` — **معطّل افتراضيًا** | إيقاف المفتاح؛ السجلات تبقى ولا تُقرأ |

## 2. السجل `pos_orders/{id}`

| الحقل | النوع | القيد على الخادم |
|---|---|---|
| `branchId` | نص | نمط المعرّف، ويجب أن يكون الكاتب عضوًا في الفرع |
| `date` | YYYY-MM-DD | يوم العمل؛ لا كتابة في فترة مقفلة (`fin_periods/locks`) |
| `kind` | `sale` / `return` | المرتجع لمدير الفرع فقط |
| `status` | `paid` / `void` | الإنشاء `paid` دائمًا |
| `no`، `dev` | نص | رقم الفاتورة ووسم الجهاز |
| `total`، `vat` | رقم | للمطابقة والتقارير دون فك البيانات |
| `digest` | SHA-256 (64 hex) | بصمة `data` |
| `data` | نص JSON ≤ 200KB | الفاتورة كاملة كما في المستند (دون حقول الإلغاء) |
| `voidData` | نص JSON ≤ 4KB | فقط عند الإلغاء: من، متى، السبب، إشعار الإلغاء |
| `by`، `at`، `cv` | | البريد = الكاتب، الوقت = وقت الخادم، إصدار التطبيق |

**القواعد (`firestore.rules` و`firestore.tenant.rules`):**
- **إنشاء:** عضو نشط في الفرع ليس للعرض فقط، بالشكل أعلاه، `status:'paid'`، خارج الفترة المقفلة. المرتجع (`kind:'return'`) لأدوار الإدارة فقط.
- **تعديل:** **الإلغاء وحده** — `paid → void` لفاتورة بيع، لأدوار الإدارة، خارج الفترة المقفلة، ولا يتغير إلا `status` و`voidData` و`by/at/cv`. **الأرقام والبيانات لا تُعدَّل أبدًا.**
- **حذف:** ممنوع على الجميع (الأرشفة لا تحذف السجل).
- **قراءة:** أعضاء الفرع والمركز (`sigRead`).
- أدوار الإدارة: `branch_manager`، `regional_manager`، `head_office`، `general_management`، `system_admin`، ومسؤول النظام.

## 3. النسخ والمطابقة (المحرك)

- `posrRecord(o)` — شكل السجل من الفاتورة (نقي، مختبر).
- `posrDiff(before, after)` — الفواتير الجديدة والتي أُلغيت (الحذف من المستند — أرشفة أو قص — **لا** يحذف السجل).
- `posrCompare(orders, recs)` — ناقص · مختلف · زائد، كما في الإغلاقات.
- `posrMirror` بالخلفية وبالترتيب بعد نجاح الحفظ — **لا يُفشل البيع أبدًا**؛ الإخفاق يُعدّ ويظهر في شاشة الصيانة.
- `posrSeed` لنسخ التاريخ القديم دفعة واحدة؛ سجل موجود بنفس البيانات لا يُعاد.

## 4. ما لا يتغير في 2a

البيع والطابور دون اتصال والإغلاق والتقارير والمحاسبة والمخزون كلها تبقى على المستند. لا ترحيل ولا حذف. البيانات الجديدة إضافة فقط.

## 5. الاختبارات

- محرك: `posrRecord`/`posrDiff`/`posrCompare`.
- قواعد على المحاكي: الكاشير ينشئ بيعًا ولا يلغي ولا يرتجع ولا يعدّل رقمًا ولا يحذف؛ المدير يلغي فقط بالحقول المسموحة؛ لا كتابة في فترة مقفلة؛ لا وصول لفرع آخر؛ الشكل والبصمة.
