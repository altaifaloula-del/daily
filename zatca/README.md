# الفاتورة الإلكترونية — المرحلة الثانية (الربط مع منصة «فاتورة»)

وحدة خادم (Node، بلا مكتبات خارجية) تنفّذ متطلبات الربط والتكامل لدى هيئة الزكاة والضريبة والجمارك.

| الملف | الوظيفة |
|---|---|
| `csr.js` | مفاتيح جهاز الإصدار (secp256k1) وطلب الشهادة CSR بقالب الهيئة وبيانات الجهاز |
| `invoice.js` | بناء الفاتورة UBL 2.1، التجزئة، التوقيع ECDSA وXAdES، رمز QR (الوسوم 1–9)، الحسابات والتقريب |
| `api.js` | واجهات المنصة: شهادة الامتثال، فحص الامتثال، شهادة الإنتاج، الإبلاغ، الاعتماد |
| `der.js` | ترميز ASN.1 DER الأدنى |

## التحقق
- `npm run test:zatca` — اختبارات بلا شبكة (ضمن مسار النشر).
- `npm run zatca:sandbox` — تحقق رسمي على بيئة المطورين لدى الهيئة: الأنواع الستة (ضريبية/مبسّطة × فاتورة/دائن/مدين) + كسور، خصم، صفري، معفى، كمية عشرية، ثم شهادة الإنتاج والإبلاغ والاعتماد. آخر تشغيل: **15/15 بلا أخطاء ولا تحذيرات**.

## ملاحظات تنفيذية
- الفاتورة تُكتب بلا مسافات بين العناصر وبالسمات مرتّبة أبجديًا، فهي بشكلها القانوني (C14N) — التجزئة = SHA-256 للنص بعد حذف `UBLExtensions` و`cac:Signature` ومرجع `QR`.
- تجزئة SignedProperties تُحسب على صيغة أداة الهيئة: `xmlns` على كل عنصر `ds` و`DigestMethod` مختصر `/>` (فحص الامتثال لا يتحقق منها؛ الإبلاغ يتحقق).
- السلسلة لكل جهاز: العدّاد ICV وتجزئة الفاتورة السابقة PIH (الأولى = `FIRST_PIH`).
- المفتاح الخاص لا يغادر الخادم أبدًا، ولا يُخزَّن في قاعدة البيانات المكشوفة للمتصفح.
